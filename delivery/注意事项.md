# n8n 适配 GaussDB — 注意事项

> 部署/使用/二次开发前必读。以下为适配过程中验证得出的关键约束与避坑点。
> 日期：2026-08-20

## 一、GaussDB O模式（Oracle 兼容）适配

当前 GaussDB 实例为 **O模式**（`datcompatibility='A'`，集中式）。O模式与原生 PG 行为有差异，适配代码已处理，二次开发时务必遵循：

| 项 | O模式行为 | 适配做法 | 不能用 |
|---|---|---|---|
| upsert | 无 `ON CONFLICT` | 用 `MERGE INTO` | `INSERT ... ON CONFLICT DO UPDATE` |
| UUID 生成 | 无 `gen_random_uuid()` / `uuid_generate_v4()` | `id varchar(36)` + 应用层 `uuid()` | `gen_random_uuid()` |
| MERGE 返回 | `MERGE INTO` 无 `RETURNING` | upsert 不返回行；如需结果 MERGE 后单独 `SELECT` | `MERGE ... RETURNING` |
| 空字符串 | 空串自动转 `NULL` | 插入空串要注意；非空约束列插空串会报错 | 假设空串保留 |
| VARCHAR 长度 | 按字节计数（非字符） | 中文/多字节字符长度计算与 PG 不同，建表 `varchar(N)` 留余量 | 按字符数估长度 |
| jsonb | `->` / `->>` / `?|` 可用 | 向量节点 metadata 过滤用 jsonb 操作符 | — |

**验证依据**：N-EXP-07（O模式兼容）、N-EXP-09（ON CONFLICT 报错）、N-EXP-10（MERGE INTO 验证）。

## 二、向量能力前置条件

| 条件 | 要求 | 说明 |
|---|---|---|
| enable_vectordb | `on` | **POSTMASTER 级，不能会话级 SET**，需改实例配置 + 重启 GaussDB。若 off，向量节点建索引会失败 |
| maintenance_work_mem | ≥512MB | 建向量索引需要。**节点会话级 `SET maintenance_work_mem='512MB'`**（GaussDB 要求值加单引号，PG 不用） |
| 版本 | Kernel 507+ | floatvector / GsIVFFLAT / GsDiskANN API 在 507 验证通过 |

**enable_vectordb 开启**（若 off）：
```bash
gs_guc reload -D <datadir> -c "enable_vectordb=on"
gs_om -t restart   # POSTMASTER 级 reload 通常无效，需 restart
```

## 三、向量维度限制（自动探测，不抛报错）

节点自动探测 GaussDB 形态（`datcompatibility` A=集中式 / ORA=分布式）+ 维度上限，自动选索引策略。**仅物理硬限给友好提示，不抛异常**（客户定位修改费劲）。

| 索引类型 | 集中式 | 分布式 |
|---|---|---|
| GsIVFFLAT | ≤1024 维 | ≤1024 维 |
| GsDiskANN（无 PQ） | ≤1024 维 | ≤1024 维 |
| GsDiskANN+PQ | **≤4096 维** | ≤1024 维（硬限） |

**pq_nseg 整除规则**：>1024 维用 GsDiskANN+PQ 时，`pq_nseg` 必须整除维度。节点算法按 `[96,128,192,256,384]` 选，不整除则回退到 `[8, dim/4]` 区间最大因子（如 1025 → 205）。

## 四、pgvector 不兼容

GaussDB 向量是**原生实现**（floatvector + GsIVFFLAT/GsDiskANN），**不是 pgvector 扩展**：

- ❌ 不能直接用 LangChain `PGVectorStore`（其 SQL 硬编码 pgvector 的 `<=>` 算子和 `vector` 类型）
- ✅ 必须用本项目 `GaussDBVectorStore`（extends LangChain `VectorStore`，用 `<+>` 算子 + `floatvector` 类型）
- 距离算子 `<+>`（cosine），**score = 1 - distance**

**验证依据**：N-EXP-04（pgvector 不兼容确认）。

## 五、连接与驱动

| 项 | 说明 |
|---|---|
| 驱动 | pg-promise / node-pg 均可连 GaussDB（PG 协议兼容）。C 维度用 pg-promise，B 维度用 node-pg |
| 默认端口 | GaussDB 默认 **8000**（非 PG 的 5432），按实际填 |
| 密码含特殊字符 | 密码含 `@` `:` `/` 等会破坏连接字符串解析。**必须用 config 对象 `pgp({host,port,user,password,database})`，不要拼连接字符串 URL** |
| 连接池 | `configureGaussDb` 不复用 `configurePostgres`（避免与 Postgres 节点连接池冲突），`nodeType:'gaussDb'` 独立池 |

## 六、构建与部署

| 项 | 说明 |
|---|---|
| **@n8n/errors ErrorOptions 修复必含** | `packages/@n8n/errors/src/types.ts` 须有 `export type ErrorOptions = { cause?: Error }`。**不含则 n8n-workflow build 失败**（`level does not exist in ExecutionBaseErrorOptions`）。这是 pre-existing bug 修复，必含于交付代码 |
| nodes-langchain dist 增量缓存 | 改源后若 dist 未更新（如 upsert 仍发 ON CONFLICT），`rm -rf dist tsconfig.build.tsbuildinfo && pnpm build` |
| 凭据类名须 `Api` 后缀 | `gaussDb` → `gaussDbApi`（lint 规则 `cred-class-name-unsuffixed`，GaussDB 不在豁免列表 CrateDb/MongoDb/Postgres/Redis/Smtp） |
| n8n 自身元数据库 | **本次未适配 GaussDB 作自身库**（A 维度 P2）。自身库用 SQLite 或 PostgreSQL，GaussDB 仅作 workflow 里连的存储 |
| build 输出重定向 | `pnpm build > build.log 2>&1`，看尾部确认 exit 0 |

## 七、使用注意

| 项 | 说明 |
|---|---|
| upsert 不返回行 | O模式 MERGE 无 RETURNING。若工作流后续需要 MERGE 后的数据，在 upsert 后接一个 select 节点单独查 |
| 向量索引维护 | 数据增删超 20% 建议重建 GsIVFFLAT 索引（影响召回率） |
| n8n 升级 | 升级时重新集成 GaussDB 适配代码（新增文件不冲突），`package.json` 的 credentials/nodes 注册行需重新加上 |
| GaussDB 版本兼容 | 507+ 已验证；<507 需测试 floatvector/索引 API 差异 |
| 端口暴露 | Docker 部署时 GaussDB 在另一主机，确保容器网络可达 GaussDB 端口 |

## 八、配置易错点

1. **GaussDB 连接不在 .env 配** — 在 n8n UI → Credentials 配（`.env` 只配 n8n 自身库 + 加密密钥）
2. **N8N_ENCRYPTION_KEY 必填** — 不设则每次重启 credentials 失效
3. **向量节点用 Postgres 凭据** — VectorStoreGaussDB 复用 "Postgres" 凭据类型（指向 GaussDB），不是 "GaussDB" 凭据
4. **凭据 Test 成功 ≠ 向量可用** — 凭据连通只验证 PG 协议；向量还需 `enable_vectordb=on`（ChatHub 凭据 test 会额外检测 enable_vectordb）
