# n8n 适配 GaussDB — 测试指南

> 本文档说明 n8n GaussDB 适配的 5 层测试方法。测试脚本在 `delivery/tests/`，自动从 `.env.test` 读配置。
> 测试前请先读 [注意事项](注意事项.md)，了解 O模式/enable_vectordb/维度限制等前置约束。
>
> `delivery/tests/` 为交付脚本，纯 python + psycopg2，不依赖 n8n 源码，已覆盖 L2 连通 / L3 数据库节点 / L4 向量。

## 测试环境准备

### 1. GaussDB 实例
确保 GaussDB 满足前置条件（见根目录 README.md 的 GaussDB 前置条件）：
- Kernel 507+，O模式（datcompatibility=A），enable_vectordb=on

### 2. 测试脚本配置
```bash
cd delivery/tests
cp .env.test.example .env.test
vi .env.test
# 填 GaussDB 连接信息：
#   GAUSSDB_HOST / GAUSSDB_PORT / GAUSSDB_USER / GAUSSDB_PASSWORD / GAUSSDB_DATABASE
```

### 3. 依赖安装（Linux）

L2/L4 用 python，L3 用 gsql 或 psql。缺失时脚本会自动 SKIP 并提示安装，不会报错。

```bash
# Debian/Ubuntu
sudo apt install -y python3 python3-pip postgresql-client
pip3 install psycopg2-binary

# Alpine
apk add python3 py3-pip postgresql-client
pip install --break-system-packages psycopg2-binary

# CentOS/RHEL
sudo yum install -y python3 python3-pip postgresql
pip3 install psycopg2-binary
```

> GaussDB 原生客户端 `gsql` 也可用于 L3（与 psql 二选一，脚本自动优先选 gsql）。

### 4. n8n 实例（L1 + UI 方式需要）
启动 n8n（见实施部署交付文档.md），创建 owner 账号。
> L2/L3/L4 的 delivery 脚本**不需要 n8n**，直连 GaussDB 即可跑。

## 一键自动化测试（推荐）

配好 `.env.test` 后，一条命令跑完 L2+L3+L4（连通 + 数据库节点 + 向量），退出码供 CI 判定：

```bash
cd delivery/tests
./run_all.sh              # 跑全部（L4 建索引约 1-3 分钟）
./run_all.sh --skip-l4    # 跳过向量（快速冒烟）
```

**分层调用**（也可单独跑某一层）：

```bash
python3 test_gaussdb_connect.py   # L2 连通性
bash   test_c_operations.sh       # L3 数据库节点 6 operation（需 gsql/psql）
python3 test_vector.py            # L4 向量全链路
python3 test_vector.py --group 1  # 只跑组1（向量 CRUD）
python3 test_vector.py --group 3  # 只跑组3（GsDiskANN+PQ 高维）
```

**CI 集成**：`run_all.sh` 退出码 0=全过 / 非0=有失败，可直接接入 CI pipeline：

```yaml
# GitHub Actions 示例
- run: cd delivery/tests && cp .env.test.example .env.test
- run: cd delivery/tests && env $(cat .env.test | xargs) ./run_all.sh
```

### Docker 快速验证（Linux，无需本地装依赖）

不想在宿主装 python/psql，可用 Docker 容器跑（自带 psql + python + psycopg2）。
适合 CI 环境或干净 Linux 验证。**注意**：容器内连宿主上的 GaussDB，host 要用 `host.docker.internal`（见下）。

```bash
cd delivery/tests

# 1. 准备 .env.test，host 改为容器可达宿主的地址
#    Linux 原生机：GAUSSDB_HOST=127.0.0.1（或 GaussDB 实际 IP）
#    Docker 容器内：GAUSSDB_HOST=host.docker.internal（连宿主上的 GaussDB）
cp .env.test.example .env.test
vi .env.test

# 2. 容器内跑全部测试（postgres:alpine 自带 psql，另装 python+psycopg2）
docker run --rm \
  --add-host=host.docker.internal:host-gateway \
  -v "$(pwd):/tests" -w /tests \
  postgres:16-alpine sh -c '
    apk add --no-cache python3 py3-pip bash >/dev/null 2>&1
    pip install --quiet --break-system-packages psycopg2-binary
    bash run_all.sh
  '
# 退出码 0 = L2+L3+L4 全通过
```

> `host.docker.internal` 在容器内解析到宿主；Linux 原生机（非容器）直接用 GaussDB 实际 IP。
> GaussDB 在远程主机时，`.env.test` 填该主机 IP，容器加 `--add-host` 或用 `--network host`。

## L3：数据库节点 6 operation 端到端

验证 GaussDb 节点 6 operation 在真实 GaussDB 可用。

### 方式一：n8n UI 手动
1. Credentials → Add → "GaussDB" → 填连接 → Test → 成功
2. 建 workflow，逐一测：
   - executeQuery：`SELECT version()` → 返回版本
   - insert：插入行 → 查表确认
   - select：查询行 → 返回数据
   - update：更新行 → 查表确认
   - upsert：MERGE INTO → 已存在行更新 + 不存在行插入
   - deleteTable：删行/删表 → 查表确认

### 方式二：SQL 层冒烟（运维可直接跑，不依赖 n8n）
```bash
cd delivery/tests
./test_c_operations.sh   # 直接对 GaussDB 跑节点会发的 SQL（gsql/psql）
```
直接对 GaussDB 执行 GaussDb 节点会发出的 SQL（O模式适配后：MERGE INTO、varchar 主键等），验证 SQL 在目标库可跑。**不依赖 n8n/tsx**，运维可直接跑。
**预期**：6 operation SQL 全通过，executeQuery 返回 `GaussDB Kernel 507.0.0`。

## L4：向量能力全链路

验证 GaussDB 向量能力（floatvector/GsIVFFLAT/GsDiskANN+PQ/`<+>`/score/维度上限/边界）。

### 方式一：自动化脚本（对外主推，不依赖 n8n）

```bash
cd delivery/tests
python3 test_vector.py            # 跑全部 4 组
python3 test_vector.py --group 1  # 只跑组1
```

覆盖 4 组：

| 组 | 验证 |
|---|---|
| 1 向量 CRUD | floatvector 建表 + 字符串字面量插入 + GsIVFFLAT 索引 + `<+>` 检索 + score=1-dist + UPDATE/DELETE |
| 2 维度上限 | GsIVFFLAT / GsDiskANN(无PQ) 在 1024/1536/4096 维建索引 |
| 3 GsDiskANN+PQ 高维 | 1536/3072/4096 维 + pq_nseg 整除（与节点算法一致）+ 检索 |
| 4 向量边界 | 空结果 filter / 超大 top-k / 零向量检索 |

- 自动探测集中式/分布式：集中式测到 4096 维；分布式 >1024 维 SKIP（不 FAIL）
- pq_nseg 算法与节点 `GaussDBVectorStore.calcPqNseg` 完全一致，保证测的是节点实际参数
- **预期**：4 组全通过（分布式跳过高维），score=1-dist 正确

### 方式二：n8n UI 端到端（集成层）

1. Credentials → Add → "Postgres"（指向 GaussDB）
2. 建 workflow：VectorStoreGaussDB + Embeddings 节点
3. insert：插入文档 + embedding
4. load：检索 top-k，确认 score 排序

### 方式三：RAG 全流程验证（mock embedding，无需真实 API）

`delivery/tests/rag/` 提供本地 OpenAI 兼容 mock 服务 + 3 个现成 workflow，验证完整 RAG 管道：Embeddings API 调用 → GaussDB 入库（1536 维自动建 GsDiskANN+PQ 索引）→ 检索 + score → AI Agent 工具链。**不需要任何真实 embedding API key**，详见 [tests/rag/README.md](tests/rag/README.md)。

> **测试层次说明**：方式一测 GaussDB 向量 SQL 契约层（GaussDB 能力本身）；节点代码逻辑层（buildFilterClauses 等）由单元测试 34 用例覆盖；方式二测 UI 端到端集成；方式三测完整 RAG 管道（含 embedding API 调用形态）。组合 = 完整验证。
